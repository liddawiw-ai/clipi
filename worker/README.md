# Clipi LiveKit on Cloudflare Workers

Use the existing Clipi Worker and its public HTTPS URL. Set its entry point to `worker.mjs`. For CLI deployment, update `name` in `wrangler.toml` to the exact name in the Cloudflare dashboard before deploying.

Set `FIREBASE_PROJECT_ID` to the Firebase project ID in `google-services.json`. Add `LIVEKIT_API_KEY` and `LIVEKIT_API_SECRET` as encrypted Worker secrets, and `LIVEKIT_URL` as the LiveKit project's `wss://` URL. Check that the Worker root returns `{"service":"clipi-livekit"}`. Put the Worker origin in the app's `EXPO_PUBLIC_CLIPI_MEDIA_URL` before building a native Expo development build or release. The LiveKit key and secret belong in Cloudflare.

The Worker authorizes room access through Firestore with the user's Firebase ID token and issues short-lived LiveKit tokens. The room document must be readable to authenticated users under the deployed Firestore rules. The host and Firestore-approved guests can publish the microphone in an audio room or microphone and camera in a video room. Viewers can subscribe. Apply the stage-request Firestore rules before testing guest access. Removing a guest updates Firestore and asks LiveKit to remove the active participant. An already issued join token can retain its original grants until expiry, so test the cloud revocation behavior before public rollout. Firebase Cloud Functions are unnecessary for this route.

Verify with two signed-in phones. Open the same audio room as host and viewer. Turn the host microphone on and off and confirm delivery. Repeat for video and camera. Close the room and confirm both app sessions exit and fresh token requests return 404. Verify that non-host accounts can't publish. The token expiry limits joining with old tokens, but does not itself disconnect a participant already connected to LiveKit. Closing a room also asks LiveKit to terminate the active session. Verify termination and token revocation against the deployed provider before public rollout.
